# Spec Delta

## Purpose

Описывает уже реализованное поведение системы отзывов `tamir.rs`: публикацию отзывов только авторизованными покупателями, анти-спам защиту, голосование за полезность и модерацию через админский API.

## ADDED Requirements

### Requirement: Публикация отзыва доступна только покупателям с аккаунтом

Запрос `POST /store/reviews` обязан (MUST) быть аутентифицирован как клиент с активным аккаунтом (`has_account`); гостям обязан (MUST) возвращаться `401` с кодом `LOGIN_REQUIRED`. Имя автора сервер обязан (MUST) брать из `profile.first_name`, а не из тела запроса.

#### Scenario: Гость пытается оставить отзыв

- **WHEN** неаутентифицированный запрос обращается к `POST /store/reviews`
- **THEN** API отвечает `401` с кодом `LOGIN_REQUIRED`

#### Scenario: Имя автора перезаписывается из профиля

- **WHEN** аутентифицированный клиент передаёт своё `name` в теле запроса
- **THEN** сохранённый отзыв создаётся с именем из `profile.first_name`, а ответ содержит `201` и объект `review`

### Requirement: Товар для отзыва обязан быть опубликован

Функция `publishedProduct` обязана (MUST) проверять формат `product_id` с префиксом `prod_` (иначе `400` `INVALID_PRODUCT`) и статус товара: несуществующий или непубликованный товар обязан (MUST) давать `404` `PRODUCT_NOT_FOUND`.

#### Scenario: Отзыв на скрытый товар

- **WHEN** `product_id` ссылается на товар со статусом, отличным от `published`
- **THEN** эндпоинт отвечает `404` с кодом `PRODUCT_NOT_FOUND`

### Requirement: Содержание отзыва проходит серверную валидацию

Функция `reviewInput` обязана (MUST) принимать имя 1–60 символов без символа `@` (пустое имя — `400` `INVALID_REVIEW`, имя с `@` — `400` `INVALID_NAME`), текст 1–250 символов без управляющих символов (иначе `400` `INVALID_REVIEW`) и оценку от 1 до 5 с шагом 0.5 (иначе `400` `RATING_REQUIRED`). Длина текста считается по кодовым точкам Unicode, а не по суррогатным парам.

#### Scenario: Пустой текст или некорректная оценка

- **WHEN** тело запроса содержит пустой `body`, `body` из 251 символа или `rating` `0`, `6`, `"5"` либо `4.7`
- **THEN** эндпоинт отвечает `400` с кодом `INVALID_REVIEW` или `RATING_REQUIRED`, отзыв не сохраняется

#### Scenario: Отображаемое имя совпадает с e-mail

- **WHEN** в `reviewInput` приходит имя с символом `@` (например, `first_name` клиента или `name` из запроса модератора)
- **THEN** валидация отвечает `400` с кодом `INVALID_NAME`

### Requirement: Отзывы защищены капчей и ограничением частоты

Перед сохранением бэкенд обязан (MUST) проверить `captcha_token` через Cloudflare Turnstile с действием `review` и разрешать (MUST) не более 10 отзывов в час на клиента (таблица `tamir_review_rate`, HMAC-ключ `review:<customer_id>`). Без секрета `REVIEW_RATE_SECRET`/`JWT_SECRET` длиной минимум 32 символа ответ обязан (MUST) быть `503` `REVIEWS_UNAVAILABLE`.

#### Scenario: Капча не пройдена

- **WHEN** `captcha_token` отсутствует, длиннее 2048 символов или не проходит проверку Turnstile (в том числе по `action` и `hostname`)
- **THEN** эндпоинт отвечает `400` с кодом `CAPTCHA_REQUIRED` или `CAPTCHA_FAILED`, отзыв не сохраняется

#### Scenario: Превышен почасовой лимит

- **WHEN** клиент отправляет одиннадцатый `POST /store/reviews` за последний час
- **THEN** эндпоинт отвечает `429` с кодом `TOO_MANY_REQUESTS`

### Requirement: Не более одного отзыва на товар

Один и тот же клиент не обязан (MUST NOT) получать возможность оставить второй отзыв на тот же товар: при нарушении уникального ограничения (SQL-состояние `23505`) API обязан (MUST) отвечать `409` с кодом `ALREADY_SUBMITTED`.

#### Scenario: Повторный отзыв на тот же товар

- **WHEN** клиент повторно отправляет `POST /store/reviews` с тем же `product_id`
- **THEN** API отвечает `409` с кодом `ALREADY_SUBMITTED`

#### Scenario: Удалённый модератором отзыв не освобождает слот

- **WHEN** отзыв переведён модератором в статус `deleted` и клиент снова отправляет `POST /store/reviews` на этот товар
- **THEN** API отвечает `409` с кодом `ALREADY_SUBMITTED`, потому что строка отзыва сохраняется в `tamir_review`
- **AND** уже отданные голоса за этот отзыв остаются в `tamir_review_vote`

### Requirement: Лента отзывов товара публична и показывает только опубликованные отзывы

`GET /store/reviews?product_id=` обязан (MUST) быть доступен без аутентификации, возвращать (MUST) только отзывы со статусом `published` (значение по умолчанию при вставке — очереди премодерации нет), устанавливать `Cache-Control: no-store` и поддерживать `offset` при фиксированной странице из 20 отзывов.

#### Scenario: Анонимный покупатель читает отзывы

- **WHEN** гость обращается к `GET /store/reviews?product_id=prod_1`
- **THEN** ответ содержит `reviews` со счётчиками `score`/`up`/`down`, поля `count` и средний `rating`, а также `has_review: false`

#### Scenario: Отметки для аутентифицированного клиента

- **WHEN** запрос пришёл с сессией клиента
- **THEN** ответ содержит `has_review: true`, если клиент уже оставлял отзыв, и `voted: true` на отзывах, где он голосовал

#### Scenario: Публичный ответ не раскрывает личные данные

- **WHEN** бэкенд формирует элементы ленты через `publicReview`
- **THEN** в ответе есть только поля `id`, `name`, `body`, `rating`, `score`, `up`, `down`, `created_at`, `voted`
- **AND** `customer_id`, `author_email`, e-mail, телефон и `metadata` в ответ отсутствуют

### Requirement: Список отзывов в админке доступен только модератору

`GET /admin/reviews` обязан (MUST) допускать только агента `actor_type: "user"`, проходящего `isReviewModerator`, иначе отвечать `403` `FORBIDDEN`, устанавливать `Cache-Control: no-store`, отдавать страницу из 30 отзывов (`offset` до 100000) и общее поле `count`. В этом списке разрешено (MAY) показывать `author_email`, `author_name` и `product_title` — эти поля недоступны ни одному публичному эндпоинту отзывов.

#### Scenario: Модератор открывает список отзывов

- **WHEN** пользователь с e-mail `admin@tamir.local` вызывает `GET /admin/reviews?offset=0`
- **THEN** ответ содержит `reviews` с полями `author_email`, `author_name`, `product_title`, `version`, `status`, `up`, `down` и общее `count`

#### Scenario: Список запрашивает покупатель или другой пользователь

- **WHEN** к `GET /admin/reviews` обращается клиент магазина или пользователь Medusa с другим e-mail
- **THEN** эндпоинт отвечает `403` с кодом `FORBIDDEN` и e-mail автора не попадает в ответ

### Requirement: Сводка рейтингов для списка товаров

`GET /store/reviews/summary` обязан (MUST) принимать `product_ids` — список до 100 идентификаторов с префиксом `prod_`, отвечать `400` `INVALID_PRODUCT` на пустой или некорректный список и возвращать объект `summaries` с `count` и `rating` по каждому товару, посчитанные только по опубликованным отзывам.

#### Scenario: Каталог запрашивает рейтинги пачкой

- **WHEN** витрина обращается к `GET /store/reviews/summary?product_ids=prod_1,prod_2`
- **THEN** ответ содержит `summaries` с `count` и `rating` для товаров с опубликованными отзывами

### Requirement: Голосование за полезность отзыва возможно только один раз

Клиент обязан (MUST) иметь возможность голосовать `+1` или `-1` через `POST /store/reviews/:id/vote`; голос обязан (MUST) храниться в `tamir_review_vote` не более одного раза на пару (отзыв, клиент) и не обязан (MUST NOT) изменяться после записи. Повторный запрос обязан (MUST) возвращать `duplicate: true` без изменения счётчиков; лимит — 60 голосов в час на клиента.

#### Scenario: Первый голос

- **WHEN** клиент впервые голосует `+1` за опубликованный отзыв
- **THEN** ответ содержит обновлённые `score`, `up`, `down`, `voted: true` и `duplicate: false`

#### Scenario: Повторное голосование не перезаписывает голос

- **WHEN** тот же клиент отправляет противоположный голос на тот же отзыв
- **THEN** ответ возвращает `duplicate: true`, счётчики не меняются

#### Scenario: Голосование за скрытый отзыв

- **WHEN** статус отзыва не `published`
- **THEN** эндпоинт отвечает `404` с кодом `REVIEW_NOT_FOUND`

### Requirement: Блок отзывов витрины открыт гостю и прячет форму от неавторизованных

Компонент `ProductReviews` обязан (MUST) показывать гостю ленту и сводку рейтинга, держать блок `product-review-content` развёрнутым по умолчанию и разворачивать его при хэше `#reviews`. Форма отзыва обязана (MUST) рендериться только авторизованному клиенту: гость вместо неё видит ссылку `reviews.signIn` на `/rs/account/login`, а клиент с `has_review: true` — сообщение `reviews.alreadyReviewed`.

#### Scenario: Гость читает отзывы и не видит форму

- **WHEN** неавторизованный посетитель открывает блок `#reviews` на странице товара
- **THEN** лента и сводка отображаются, контейнер `product-review-content` не скрыт
- **AND** вместо формы отзыва показана ссылка на `/rs/account/login`

#### Scenario: Повторная форма для автора отзыва отсутствует

- **WHEN** ответ `GET /store/reviews` для вошедшего клиента содержит `has_review: true`
- **THEN** в блоке `#review-write` показан текст `reviews.alreadyReviewed` и форма отзыва не появляется

### Requirement: Отрицательно оценённый отзыв свёрнут по умолчанию

Компонент `ReviewItem` обязан (MUST) скрывать текст отзыва, если `reviewCollapsed(score)` истинно (`score < 0`), подписывать его как скрытый (`reviews.hiddenNegative`) и раскрывать только после нажатия кнопки с `aria-controls="review-body-<id>"`; порядок ленты обязан (MUST) оставаться по дате создания. Кнопки голосов для гостя обязаны (MUST) быть ссылками на `/rs/account/login`, а не запросами к API.

#### Scenario: Читатель раскрывает свёрнутый отзыв

- **WHEN** у отзыва `score` меньше нуля
- **THEN** контейнер `review-body-<id>` скрыт и показана подпись `reviews.hiddenNegative`
- **AND** нажатие кнопки переключения делает текст видимым, повторное нажатие снова скрывает его

#### Scenario: Гость нажимает «полезно»

- **WHEN** неавторизованный посетитель нажимает кнопку полезности у отзыва
- **THEN** запрос к `POST /store/reviews/:id/vote` не отправляется, открывается ссылка `/rs/account/login`

### Requirement: Модерация отзыва сохраняет версию и след в аудите

Редактирование через `POST /admin/reviews/:id` обязано (MUST) быть доступно только пользователю, проходящему `isReviewModerator` (email `admin@tamir.local`), иначе — `403` `FORBIDDEN`. Запрос обязан (MUST) передать текущий `version`; при несовпадении ответ — `409` `REVIEW_CHANGED`. Любое изменение обязано (MUST) увеличивать `version` и записывать строку в `tamir_review_audit`.

#### Scenario: Одновременное редактирование двумя модераторами

- **WHEN** переданный `version` не совпадает с сохранённым
- **THEN** эндпоинт отвечает `409` с кодом `REVIEW_CHANGED`, изменения не применяются

#### Scenario: Правка текста и статуса

- **WHEN** модератор передаёт `body` и/или `status` (`published`, `hidden`, `deleted`) с корректным `version`
- **THEN** `version` увеличивается, в `tamir_review_audit` добавляется строка с предыдущим состоянием, ответ — `{ success: true }`

#### Scenario: Рейтинг недоступен для правки модератором

- **WHEN** тело запроса содержит поля `rating` или счётчики голосов
- **THEN** эти поля игнорируются, сохранённые значения не меняются

### Requirement: Конфигурация подсистемы отзывов проверяется до деплоя

Скрипт деплоя обязан (MUST) запускать `scripts/check-review-config.cjs` и обязан (MUST) останавливать выпуск при коротких (<32 символа) `JWT_SECRET`/`COOKIE_SECRET`, отсутствии ключей Turnstile, `REVIEW_RATE_SECRET` или корректного SMTP (порт `587`/`465`).

#### Scenario: Секрет не настроен

- **WHEN** на сервере не задан `REVIEW_RATE_SECRET`
- **THEN** проверка завершается ошибкой, деплой не выполняется
