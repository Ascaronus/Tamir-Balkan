# Дизайн: UX авторизации в шапке и модалка входа (TB-13)

## Context

UX-контракт ТЗ: гостю — кнопка «Prijavi se» / «Sign in» в шапке, открывающая модалку входа с кнопкой регистрации; авторизованному — имя вместо кнопки; сессия восстанавливается после перезагрузки; пользователь не покидает текущую страницу.

Реализация частично уже в main (коммиты `9b64517`, `d9e958e`, `318146c`):

| Кнопка в шапке для гостя | `HeaderAccount` → `t("auth.login.signIn")` = «Prijavi se» / «Sign in» | есть |
| Модалка поверх страницы | `LoginDialog` — нативный `<dialog>`, `showModal()`, затемняющий фон, ширина `min(440px, 100vw-32px)`, блокировка scroll | есть |

Оставшиеся расхождения, которые закрывает этот change: (1) Figma-макет не обновлён; (2) мобильная панель `UserNav` ведёт на `/account/register` (страницей, не модалкой) и использует ключ `auth.signIn`, а не таблицу `auth.login.*` / `headerAuth.*` из ТЗ; (3) сценарии ошибки входа и состояния отправки не покрыты тестами; (4) UX-требование нигде не зафиксировано как спецификация.

## Goals / Non-Goals

**Goals:**
- Зафиксировать UX-контракт TB-13 как ADDED-требования capability `customer-auth` (не противореча существующим API-требованиям).
- Обновить Figma-макет до реализации.
- Привести оставшиеся расхождения (мобильная панель, тексты) к спецификации и дотестировать сценарии ошибки/загрузки.

**Non-Goals:**
- Не менять контракт регистрации (коды доступа, лимиты, троттлинг) — существующая спецификация `customer-auth` остаётся как есть.
- Не менять BFF `/api/auth/*`, Medusa-аутентификацию, структуру сессий.
- Не менять layout header, не добавлять новый capability.
- Не реализовывать E2E в этом репозитории (внешние E2E — Tamir-QA-Automation, TESTING-RULES §1).

## Decisions

1. **Модалка вместо страницы для входа** (как требует ТЗ) — при этом страницы `/account/login` и `/rs/nalog/prijava` остаются доступны по прямому URL и открывают ту же модалку (`searchParams login=open`). Альтернатива «только страница» отвергнута: ТЗ требует сохранения текущего местоположения пользователя.

2. **Нативный `<dialog>` + `showModal()`** (уже так) — даёт ловушку фокуса, Escape и затемняющий фон (`::backdrop`) без зависимостей; `onClose` возвращает фокус на триггер шапки. Не переписывать на headless-библиотеку.

3. **«Registruj se» — навигационная ссылка, не submit** — `<Link>` на существующую страницу регистрации в той же локали. В модалке используется `/{cc}/account/register`, который для `/rs` редиректит на `/rs/nalog/registracija` (покрыто `verify-localized-routes.mjs`). Менять маршрут в компоненте не требуется; в спецификации фиксируется целевой локализованный маршрут.

4. **Имя: `first_name` → `display_name` → префикс email** — утилита `frontend/src/lib/auth/customer-display-name.ts` уже реализует приоритет ТЗ; усечение — CSS (`max-width` + ellipsis), высота header фиксирована классами `header-account-*`.

5. **Синхронизация мобильной панели `UserNav`** — решение: оставить page-based вход на мобильной панели (узкий экран, модалка из `<details>`-панели конфликтует с её поведением), но привести подписи к таблице ТЗ (`auth.login.*`), чтобы ключи и тексты были едиными в обоих брейкпоинтах. Это единственное ожидаемое изменение в коде — объём уточняется задачей 2.2 в tasks.

6. **Тесты** — расширяем существующий `frontend/tests/header-authentication.test.mjs` (маска `frontend/tests/*.test.mjs` из TESTING-RULES §1): сценарии ошибки входа, состояния кнопки, полного набора sr/en текстов по таблице ТЗ. Интеграционная проверка маршрутов уже в `frontend/test-support/verify-localized-routes.mjs` — только дополняем при необходимости. Новые внешние E2E не добавляем.

## Risks / Trade-offs

- [Слабление существующих тестов при расширении] → TESTING-RULES §4: существующие проверки только усиливаются, имена не удаляются; review-diff теста обязателен.
- [Разъезд текстов `UserNav` и таблицы ТЗ после частичной синхронизации] → тест локализации сверяет обе области (`headerAuth.*`, `auth.login.*`) со словарями.
- [Figma-прототип недоступен по fileKey (ссылка дана как prototype ID)] → задача Figma выполняется вручную/через Figma MCP с уточнением файла; без обновлённого макета implementation не начинается (мандат PROCESS-RULES).
- [Прямой URL `/account/login` без JS-hydratation] → модалка открывается из server-side `searchParams`, сценарий уже существует; регрессия покрывается тестом маршрутов.

## Migration Plan

Развёртывание обычное (Vercel frontend, TESTING-RULES §7). Раскатка не требуется: изменения UI-совместимы, сессии и cookie не меняются. Откат — revert коммита change; спецификация возвращается архивацией без применения.
