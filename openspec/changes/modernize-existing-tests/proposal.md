# Предложение: modernize-existing-tests

## Why

Набор тестов Tamir-Balkan вырос стихийно: backend-тесты запускаются в CI
ручным списком (новый файл молча не попадает в прогон), самые ценные проверки
реальных HTTP-границ почти отсутствуют, а часть наборов (`registration-email`,
Jest-суита Medusa, `rozetka-native`) вообще не исполняется в CI. Аудит
`docs/02_EXISTING_TESTS_AUDIT.md` фиксирует это как долг; модернизация нужна,
чтобы CI честно доказывал работоспособность витрины, не ломая уже полезные тесты.

## What Changes

- Каталогизация существующих тестов: каждый тест получает слой и честное
  описание того, что он доказывает; baseline прогонов снимается до изменений.
- Сохранение всех полезных unit/component/mocked/db-тестов: никаких массовых
  удалений, усилениеcoverage идёт добавлением тестов более высокого слоя.
- Discovery в CI: backend-тесты обнаруживаются по шаблону имени файла вместо
  ручного перечисления в `verify.yml`; неохваченные наборы включаются в CI или
  получают задокументированный ручной порядок; результаты публикуются
  машиночитаемыми отчётами (JUnit) с артефактами. Покрытие всех наборов —
  обязательное условие.
- Реальные HTTP-интеграционные тесты in-app (`medusaIntegrationTestRunner`) для
  `/health` и кастомных store-маршрутов (в т.ч. `GET /api/store/catalog/products`
  с налоговым контекстом), включая негативные проверки авторизации.
- Единый контракт изолированной тестовой среды: одноразовые БД и секреты,
  защитный барьер против боевого окружения, независимость от порядка тестов.
- Локализационные проверки на реальных en/sr строках витрины, парность
  маршрутов `/rs` и `/en` уже исполняемым скриптом.
- Граница: браузерные E2E и black-box проверки развёрнутых стендов остаются
  в репозитории Tamir-QA-Automation и здесь не дублируются.
- Поведение приложения не меняется: change только про тесты, CI и документацию.

## Capabilities

### New Capabilities

- `testing/test-classification-baseline`: классификация каждого теста по слою,
  baseline прогонов и честные границы доказательств каждого слоя.
- `testing/test-suite-preservation`: запрет массовых удалений, цепочка
  «исходный тест → пробел → тест высшего слоя → результат», сохранение числа проверок.
- `testing/ci-test-discovery`: автоматическое обнаружение backend-тестов в CI,
  покрыте всех наборов прогоном или задокументированным порядком, машиночитаемые
  отчёты.
- `testing/http-integration-tests`: HTTP-интеграция in-app против реальной базы
  Medusa для `/health` и кастомных маршрутов, позитив и негатив авторизации,
  граница с Tamir-QA-Automation.
- `testing/isolated-test-environment`: только одноразовые БД/секреты, барьер
  против боевого окружения, независимость от порядка выполнения.
- `testing/localization-coverage`: проверки на реальных en/sr строках витрины,
  парность локализованных маршрутов в CI, сохранение поведения выбора локали.

### Modified Capabilities

(нет — базовые application-спеки из change `document-current-behavior` ещё не
перенесены в `openspec/specs/`, поэтому все дельты объявлены как новые
возможности в пространстве `testing/`)

## Impact

- `.github/workflows/verify.yml` — discovery-паттерны, новые шаги (Jest HTTP-набор,
  `registration-email`, отчёты/JUnit, артефакты).
- `backend/tests/`, `backend/integration-tests/` — новые HTTP-тесты и,
  возможно, переименования с сохранением истории; `backend/package.json` при
  необходимости.
- `frontend/tests/` — новые локализационные проверки; существующие 28 файлов
  сохраняются.
- `docs/TESTING.md` — актуальный порядок прогонов и классификация.
- Влияния на рантайм-код приложения (`backend/src`, `frontend/src`) нет.
