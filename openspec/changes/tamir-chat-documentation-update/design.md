# Design

## Context

См. `proposal.md` — мотивация (TB-11: документация по чату отстаёт от кода после PR #96, #110–#114). Текущее состояние: `docs/TAMIR-CHAT.md` (326 строк) частично устарел; `docs/TESTING.md` не каталогизирует чат-тесты; требований к актуальности документации в `openspec/specs/tamir-chat/spec.md` нет. Требования дельты — в `specs/tamir-chat/spec.md` этого изменения.

## Goals / Non-Goals

**Goals:**
- Определить способ аудита и структуру обновлённой документации, чтобы задачи реализации были однозначны.
- Зафиксировать критерий «документация соответствует коду» как проверяемый (пути, эндпоинты, команды).

**Non-Goals:**
- Перевод документации на другие языки (кроме уже существующих локалей, если они не затрагиваются).
- Переписывание основного спика `openspec/specs/tamir-chat/spec.md` (дельта добавляет требования, архив перенесёт их).
- Изменение кода чата, тестов, CI, деплоя.

## Decisions

1. **Один канонический документ, а не набор новых файлов.** Основной — `docs/TAMIR-CHAT.md`; он обновляется, а не создаётся заново: сохраняет существующую структуру и ссылки, снижает риск расхождения двух версий. Альтернатива (новый `docs/chat/` каталог) отклонена: в `docs/` принят плоский формат одиночных документов на тему.
2. **Аудит по git-истории, а не «на глаз».** Опора на diff PR #96, #110–#114 (`git log --grep` по merge-коммитам и diff веток) для получения фактического перечня затронутых файлов; дальше — сверка перечня файлов чата в репозитории с перечнем в документе. Это делает покрытие проверяемым требованием дельты.
3. **Чат-тесты каталогизируются в `docs/TESTING.md`, а не в TAMIR-CHAT.md.** Каталог тестов уже живёт в `docs/TESTING.md` (таблицы frontend/backend); дублировать его в документе чата — второй источник истины. В `docs/TAMIR-CHAT.md` остаётся ссылка на каталог. Альтернатива (полный список тестов в TAMIR-CHAT.md) отклонена из-за дублирования.
4. **Учёт необъединённых PR #112–#114 как «ожидаемых».** На момент планирования в локальной истории видны #96, #97, #110, #111 и локальный коммит `1f9de9a`. Аудит выполняется против актуального `main` на момент реализации; если #112–#114 ещё не объединены, их содержимое помечается в документе как ожидаемое или не включается — решение принимается по факту наличия кода, чтобы не описывать несуществующее поведение.

## Risks / Trade-offs

- [PR #112–#114 ещё не в `main`] → аудит выполняется непосредственно перед правками; документ описывает только код, присутствующий в ветке на момент задачи.
- [Документация может снова устареть после изменения кода] → добавленные требования дельты делают рассинхрон проверяемым; при будущих чат-PR документ входит в чек-лист задач.
- [Риск задеть несвязанные разделы `docs/TESTING.md`] → правки только в таблицах чат-тестов и командах чата; остальной файл не трогать.
