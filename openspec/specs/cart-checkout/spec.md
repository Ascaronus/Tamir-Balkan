# cart-checkout Specification

## Purpose
Фиксирует текущее поведение корзины и оформления заказа tamir.rs: создание корзины через Medusa Store API (medusa js-sdk), хранение гостевого идентификатора в `localStorage` и восстановление корзины аккаунта с сервера, изменение позиций, предпросмотр корзины из шапки и пошаговое оформление с доставкой и оплатой при получении в валюте RSD.

## Requirements

### Requirement: Cart is created through the Store API with a region chosen by shipping country

Для гостя `sdk.store.cart.create` обязана (MUST) вызываться с `region_id` региона, подобранного по стране доставки (`getRegionByCountry`), и `shipping_address.country_code`; параллельные обращения одной страницы к корзине для той же страны и текущего владельца обязаны (MUST) переиспользовать один общий незавершённый запрос (`pendingCarts`).

#### Scenario: First cart for Serbia

- **WHEN** пользователь впервые добавляет товар и сохранённой корзины нет
- **THEN** frontend создаёт корзину через `POST /store/carts` с `region_id` сербского региона и `country_code: rs`
- **AND** корзина работает в валюте RSD

### Requirement: Guest cart id is stored in localStorage under the tb_cart_id key

Frontend обязана (MUST) хранить id активной гостевой корзины в `window.localStorage` под ключом `tb_cart_id` и переиспользовать её при повторных визитах; если сохранённая корзина не найдена (404) или уже завершена (`completed_at`), frontend обязана (MUST) сбросить `tb_cart_id` и создать новую корзину, а при смене страны — обновить `region_id` существующей корзины.

#### Scenario: Returning visitor with an active cart

- **WHEN** гостевая страница обращается к корзине и в `localStorage` есть `tb_cart_id`
- **THEN** frontend загружает эту корзину через `GET /store/carts/{id}` и не создаёт новую

#### Scenario: Saved cart is already completed

- **WHEN** корзина по сохранённому id имеет `completed_at` или отсутствует на бэкенде
- **THEN** frontend удаляет `tb_cart_id`
- **AND** создаёт новую корзину

### Requirement: Cart line items are changed through js-sdk methods

Frontend обязана (MUST) добавлять, изменять количество и удалять позиции через `sdk.store.cart.createLineItem`, `updateLineItem` и `deleteLineItem` с проверкой положительного количества (`requireQuantity`); при ошибке «корзина уже завершена» добавление обязана (MUST) повторить на новой корзине.

#### Scenario: Changing a line item quantity

- **WHEN** пользователь меняет количество позиции в корзине
- **THEN** frontend вызывает `sdk.store.cart.updateLineItem` с новым количеством
- **AND** обновлённая корзина отображается без перезагрузки страницы

### Requirement: Checkout goes through the address, shipping and payment steps on the checkout page

Страница checkout обязана (MUST) проводить оформление последовательно: адреса и e-mail (`sdk.store.cart.update`), вариант доставки (`GET /store/shipping-options` + `sdk.store.cart.addShippingMethod`), платёжная сессия (`sdk.store.payment.initiatePaymentSession`) и завершение корзины (`sdk.store.cart.complete`). Провайдер оплаты берётся из `GET /store/payment-providers?region_id=` — это провайдер с подстрокой `system` в `id` (в нижнем регистре), а не константа.

#### Scenario: Successful checkout

- **WHEN** пользователь отправил корректный адрес, выбрал доставку и подтверждает заказ
- **THEN** frontend проставляет в корзину `email`, `shipping_address` и `billing_address`, выбирает способ доставки, инициализирует платёжную сессию провайдером с `system` в `id`
- **AND** `billing_address` при этом копируется из `shipping_address`
- **AND** завершает корзину и получает заказ

#### Scenario: No shipping options available

- **WHEN** для введённого адреса `GET /store/shipping-options` возвращает пустой список
- **THEN** frontend показывает ошибку и не создаёт заказ

#### Scenario: No cash-on-delivery payment provider in the region

- **WHEN** `GET /store/payment-providers?region_id=...` не содержит провайдера с `system` в `id`
- **THEN** frontend показывает сообщение об ошибке и не вызывает `sdk.store.cart.complete`
- **AND** корзина остаётся незавершённой

### Requirement: Guest checkout is available without sign-in

Оформление обязана (MUST) быть доступно неавторизованному посетителю: на странице checkout показывается выбор «продолжить как гость» или «войти», заказ создаётся по введённому e-mail без обязательного входа; для авторизованного покупателя frontend обязана (MUST) предлагать использовать данные аккаунта.

#### Scenario: Checkout without signing into an account

- **WHEN** неавторизованный пользователь заполняет форму и подтверждает заказ
- **THEN** заказ создаётся без требования входа
- **AND** в заказе сохраняется указанный e-mail

### Requirement: After checkout the cart is cleared and the confirmation is read from sessionStorage

После успешного `complete` frontend обязана (MUST) сохранить квитанцию заказа (`id`, `display_id`, `total`, `currency_code`) в `sessionStorage` под ключом `tamir_order_receipts`, удалить `tb_cart_id` при гостевом оформлении (сохранив отдельную гостевую корзину при оформлении аккаунта) и перейти на `/rs/order/{id}` или `/en/order/{id}`; страница подтверждения обязана (MUST) сначала читать квитанцию из `sessionStorage`, затем — `GET /store/orders?id=...` (для авторизованных), иначе показывать состояние «не подтверждено».

#### Scenario: Navigation to the confirmation page

- **WHEN** `sdk.store.cart.complete` возвращает объект заказа
- **THEN** frontend сохраняет квитанцию в `sessionStorage`, очищает указатель завершённой гостевой корзины, если оформлял гость, и переходит на `/order/{id}`
- **AND** страница показывает номер `display_id` подтверждённого заказа

#### Scenario: Guest opens the confirmation page directly without a receipt

- **WHEN** гость открывает `/rs/order/{id}` в другой вкладке, где `sessionStorage` не содержит квитанции
- **THEN** страница показывает сообщение «не подтверждено» с подсказкой вернуться в браузер покупки или войти
- **AND** данные чужого заказа не раскрываются

### Requirement: Product card shows the public shipping price from Medusa

Карточка обязана (MUST) получать актуальный тариф доставки по Сербии из методов
Medusa для профиля товара и доступного канала, без создания корзины. Самовывоз,
возвраты и отключённые методы не должны (MUST NOT) подменять стоимость доставки.
Цены запрашиваются без кэша; ноль отображается как «Besplatno» / «Free».
Если цены отличаются, карточка обязана (MUST) показать методы с их ценами.
Неизвестный или calculated-тариф требует уточнения при оформлении; ошибки API
не должны (MUST NOT) превращаться в бесплатную доставку. SEO получает те же
данные вместо фиксированных 300 RSD. Окончательная стоимость по адресу, корзине
и персональным условиям по-прежнему рассчитывается существующим checkout.

#### Scenario: Shipping rate changed in the admin

- **GIVEN** метод доставки доступен профилю товара в Сербии
- **WHEN** в админке его цена изменена с 300 на 0
- **THEN** после загрузки карточки показано «Besplatno» / «Free»
- **AND** при последующем изменении на 450 показана соответствующая сумма RSD

#### Scenario: Fetching the rate fails

- **WHEN** стоимость доставки получить не удалось
- **THEN** карточка предлагает уточнить стоимость при оформлении
- **AND** не отображает устаревшие 300 RSD или бесплатную доставку


### Requirement: Shipping method names match the storefront language

Список способов доставки, выбранный метод в итоговом блоке checkout и список
методов в карточке товара MUST использовать единый перевод известных общих
названий. SR использует сербскую латиницу, EN — английский. Пробелы по краям,
регистр и повторные пробелы не влияют на распознавание. Перевод MUST NOT менять
ID метода, доступность, цену или запрос выбора доставки. Неизвестные имена
перевозчиков и пользовательских услуг сохраняются без догадок о значении.

#### Scenario: The Shipping method from the admin

- **GIVEN** Medusa вернула метод с названием ` Shipping`
- **WHEN** пользователь выбирает доставку на SR или EN
- **THEN** название отображается как `Dostava` или `Delivery` соответственно
- **AND** итоговый блок заказа использует тот же перевод
- **AND** запрос выбора содержит исходный ID метода

#### Scenario: Standard, express shipping and pickup

- **GIVEN** название является известным общим названием на английском или сербском
- **THEN** витрина показывает его в выбранной локали
- **AND** произвольное название вроде `D Express — 24h` остаётся исходным


### Requirement: Cart updates do not replace the form with a loading screen

Общие провайдеры аккаунта, корзины и избранного MUST располагаться выше страниц.
Переход на корзину/checkout обновляет данные корзины в фоне, сохраняя уже показанное
содержимое; смена языка того же маршрута не инициирует повторную загрузку корзины.
Удаление позиции MUST сохранять переводы остальных товаров. Новые товары получают
переводы пакетно, отдельно от денежных данных. Новая корзина, локаль и явный retry
инвалидируют соответствующие данные; суммы всегда берутся из ответа Medusa.
После завершения заказа и выхода из аккаунта состояние корзины MUST очищаться;
запоздалый ответ предыдущей сессии не должен восстанавливать его.

#### Scenario: Choosing a different shipping method

- **WHEN** запрос выбора доставки выполняется
- **THEN** поля формы, варианты доставки и последний подтверждённый расчёт остаются видимыми
- **AND** показывается статус обновления доставки, а не отправки заказа
- **AND** ошибка сохраняет предыдущий подтверждённый выбор и позволяет повторить действие
- **AND** повторное нажатие уже выбранного метода не отправляет запрос

#### Scenario: First load of payment methods

- **WHEN** провайдеры оплаты ещё загружаются
- **THEN** форма остаётся видимой; отсутствие методов и кнопка retry не показываются до результата
- **AND** строки доставки и общей суммы существуют до расчёта, но неизвестные суммы отображаются как «—»

### Requirement: Account cart is preserved after sign-out

Система MUST восстанавливать последнюю незавершённую корзину аккаунта по подтверждённой
серверной привязке, региону и каналу продаж через POST /store/customer-cart. Совпадение email
и обычный Medusa customer_id MUST NOT считаться подтверждённой привязкой. Клиент MUST NOT
выбирать владельца в теле запроса или хранить приватный ID корзины аккаунта в localStorage.

#### Scenario: Signing in again

- **WHEN** покупатель выходит и снова входит, в том числе с другого устройства
- **THEN** сервер возвращает его сохранённую незавершённую корзину с исходными строками и количеством
- **AND** во время выхода, смены аккаунта и восстановления чужие предыдущие данные не отображаются
- **AND** запоздавший ответ предыдущей сессии не заменяет корзину текущего покупателя

#### Scenario: Guest cart at sign-in

- **WHEN** у аккаунта ещё нет корзины и посетитель предъявляет пригодную гостевую корзину
- **THEN** сервер привязывает её авторизованному покупателю, очищается только успешно привязанный гостевой указатель
- **AND** если корзина аккаунта уже существует, она имеет приоритет, отдельная гостевая корзина сохраняется без автоматического объединения

#### Scenario: Linked cart is protected

- **WHEN** анонимный пользователь или другой аккаунт читает, меняет, завершает или переносит привязанную корзину
- **THEN** сервер отклоняет запрос (401 без авторизации, 404 чужому владельцу)
- **AND** гостевое оформление с email существующего аккаунта остаётся доступным

### Requirement: Reduced stock is shown without deleting saved line items

При входе в корзину frontend MUST сверять сохранённые количества со свежей доступностью
Medusa с учётом резервов. Ошибка запроса MUST NOT трактоваться как нулевой остаток.

#### Scenario: Item sold out or stock reduced

- **WHEN** доступно 0 или меньше сохранённого количества
- **THEN** соответствующая строка сразу показывает SR/EN предупреждение с доступным количеством
- **AND** количество и строка не изменяются автоматически
- **AND** удаление/уменьшение доступны, переход к оформлению из корзины заблокирован до устранения известного превышения
- **AND** числовой остаток не показывается заранее для строк с достаточным количеством

#### Scenario: Reducing a saved quantity down to the available stock

- **WHEN** в строке 3 штуки, доступна 1 и покупатель нажимает «−»
- **THEN** frontend отправляет штатную мутацию количества сразу со значением 1
- **AND** учитывает количество того же варианта в других строках
- **AND** при достаточном остатке уменьшает количество на одну штуку
- **AND** если положительного допустимого количества нет, уменьшение недоступно, остаётся явное удаление
- **AND** ошибка мутации сохраняет прежнее количество и показывает ошибку

### Requirement: Cart preview opens on hover

Шапка интернет-магазина SHALL показывать иконку корзины, при наведении курсора на которую открывается всплывающий предпросмотр корзины (mini cart) без перехода на другую страницу. Предпросмотр SHALL открываться после задержки 150–200 мс удержания курсора и SHALL НЕ открываться при случайном быстром проходе курсора. Открытие предпросмотра SHALL НЕ вызывать сетевых запросов: данные берутся из текущего состояния корзины.

#### Scenario: Deliberate hover opens the preview

- **WHEN** пользователь удерживает курсор на иконке корзины дольше задержки открытия (150–200 мс)
- **THEN** под иконкой появляется предпросмотр корзины с текущим содержимым
- **AND** страница не перезагружается и пользователь остаётся на текущей странице

#### Scenario: A quick cursor pass does not open the preview

- **WHEN** пользователь быстро проводит курсором по иконке корзины (быстрее задержки открытия)
- **THEN** предпросмотр не открывается

#### Scenario: Opening makes no network requests

- **WHEN** предпросмотр открывается
- **THEN** содержимое отображается из локального состояния корзины без новых запросов к backend

### Requirement: Cart preview closes by behaviour and gestures

Предпросмотр корзины SHALL закрываться: при уходе курсора с иконки и самого предпросмотра (с задержкой 150–250 мс, чтобы можно было зайти в предпросмотр), по клавише Escape, по клику/нажатию вне предпросмотра. Переход курсора из иконки в предпросмотр SHALL NOT закрывать его.

#### Scenario: Close delay allows entering the preview

- **WHEN** пользователь убирает курсор с иконки корзины и в пределах задержки закрытия (150–250 мс) заходит курсором в область предпросмотра
- **THEN** предпросмотр остаётся открытым

#### Scenario: Escape closes the preview

- **WHEN** предпросмотр открыт и пользователь нажимает Escape
- **THEN** предпросмотр закрывается, фокус возвращается на иконку корзины

#### Scenario: Click outside closes the preview

- **WHEN** предпросмотр открыт и пользователь нажимает в любую область вне иконки корзины и предпросмотра
- **THEN** предпросмотр закрывается

### Requirement: Cart preview contents

Предпросмотр SHALL перечислять позиции корзины: миниатюру изображения (~60×75 px), локализованное название товара (полное, с переносом), атрибуты варианта, количество, цену единицы и стоимость позиции с учётом количества, отформатированную в валюте и формате текущей локали.

#### Scenario: Line items with variant attributes

- **WHEN** в корзине есть товар с вариантом (например, размер 42, цвет black)
- **THEN** в предпросмотре показаны миниатюра, локализованное название, атрибуты варианта и итог позиции

### Requirement: Subtotal and cart button in the preview

Внизу предпросмотра SHALL отображаться итог (subtotal) и кнопка «View cart» («Pogledaj korpu»). При переполнении списка прокручивается список позиций, а футер с итогом и кнопкой SHALL оставаться закреплённым внизу.

#### Scenario: Many line items and scrolling

- **WHEN** в корзине больше позиций, чем помещается в предпросмотр
- **THEN** показывается не более установленного максимума позиций, остальное доступно вертикальной прокруткой
- **AND** итог и кнопка «View cart» видны всегда (footer закреплён)

#### Scenario: Subtotal updates without a page reload

- **WHEN** пользователь меняет количество или удаляет позицию (из предпросмотра или со страницы корзины)
- **THEN** содержимое и итог предпросмотра обновляются сразу, без перезагрузки страницы

### Requirement: Empty cart in the preview

При пустой корзине предпросмотр SHALL показывать локализованное сообщение «Your cart is empty» («Korpa je prazna») и SHALL NOT показывать итог и кнопку «View cart».

#### Scenario: Empty cart on hover

- **WHEN** корзина пуста и пользователь наводит курсор на иконку корзины
- **THEN** предпросмотр показывает только локализованное сообщение о пустой корзине
- **AND** итог и кнопка «View cart» скрыты

### Requirement: Clicking a preview line item leads to the product page

Клик по строке товара в предпросмотре SHALL вести на страницу этого товара (локализованный URL товара, при наличии варианта — с выборкой варианта). Клик по кнопке «View cart» SHALL вести на страницу корзины.

#### Scenario: Navigation to the product

- **WHEN** пользователь кликает по строке товара в предпросмотре
- **THEN** открывается локализованная страница этого товара

#### Scenario: Navigation to the cart

- **WHEN** пользователь кликает «View cart» в предпросмотре
- **THEN** открывается локализованная страница корзины

### Requirement: Mobile cart behaviour without hover

На устройствах без hover (тач/pen) тап по иконке корзины SHALL открывать «закреплённый» предпросмотр: он SHALL NOT закрываться сам и SHALL закрываться повторным тапом по иконке корзины, клавишей Escape или нажатием вне предпросмотра. Переход на страницу корзины SHALL быть доступен через кнопку «View cart» в предпросмотре.

#### Scenario: Tap on the cart icon on a phone

- **WHEN** пользователь на тач-устройстве нажимает на иконку корзины в шапке
- **THEN** появляется закреплённый предпросмотр корзины с текущим содержимым
- **AND** предпросмотр остаётся открытым после отпускания пальца

#### Scenario: Closing the pinned preview

- **WHEN** закреплённый предпросмотр открыт и пользователь повторно тапает по иконке корзины, нажимает Escape или тапает вне предпросмотра
- **THEN** предпросмотр закрывается

#### Scenario: Navigating to the cart page from a phone

- **WHEN** в закреплённом предпросмотре пользователь тапает «View cart»
- **THEN** открывается локализованная страница корзины

### Requirement: Preview size and positioning

Ширина предпросмотра SHALL быть фиксированной в диапазоне 340–400 px (текущая реализация — 380 px). Высота SHALL ограничиваться максимумом 450–550 px с внутренней вертикальной прокруткой; позиционирование SHALL быть под иконкой корзины с выравниванием по правому краю при достаточной ширине экрана и SHALL подстраиваться под границы вьюпорта. Предпросмотр SHALL не ломать раскладку шапки и не перекрывать другие её элементы за пределами своего слоя.

#### Scenario: Short viewport

- **WHEN** предпросмотр открыт во вьюпорте с небольшой высотой
- **THEN** высота предпросмотра ограничена доступной областью, список позиций прокручивается
- **AND** предпросмотр полностью виден внутри вьюпорта

### Requirement: Cart preview accessibility

Иконка корзины SHALL оставаться доступной кнопкой/ссылкой с корректной подписью; предпросмотр SHALL управляться с клавиатуры: фокус на элементе корзины, установленный с клавиатуры, открывает предпросмотр, Tab позволяет перемещаться по позициям и кнопкам предпросмотра, Escape закрывает предпросмотр и возвращает фокус на элемент корзины.

#### Scenario: Keyboard navigation

- **WHEN** пользователь переводит фокус на элемент корзины с клавиатуры
- **THEN** предпросмотр открывается, Tab перемещает фокус по его интерактивным элементам
- **AND** Escape закрывает предпросмотр и возвращает фокус на элемент корзины

### Requirement: Single source of cart state

Предпросмотр корзины SHALL использовать то же состояние корзины, что и остальные элементы магазина (провайдер состояния корзины), и SHALL NOT вводить собственную логику корзины, отдельные хранилища или отдельные запросы. Данные предпросмотра (позиции, цены, локализованные названия) SHALL обновляться синхронно с изменениями состояния корзины.

#### Scenario: No duplicated cart logic

- **WHEN** товар добавляется в корзину со страницы товара
- **THEN** счётчик корзины в шапке и содержимое предпросмотра отражают одно и то же состояние корзины
