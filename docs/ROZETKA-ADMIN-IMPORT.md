# Импорт Rozetka через админку

Страница: `/app/rozetka`, пункт меню **Импорт Rozetka**. Доступна вошедшим администраторам.

1. Выберите **По ссылке** или **XML-файл**. По умолчанию указан `https://tamir.ua/ua/rozetka/`; адрес можно редактировать (HTTPS на tamir.ua). Файл — XML/YML в UTF-8 до 10 МБ. Нажмите **Загрузить товары**: просмотр не изменяет каталог магазина. Импорт использует именно загруженный источник; изменение поля ссылки без загрузки не переключает каталог. XML-файл не сохраняется в браузерном хранилище: после перезагрузки выберите его снова.
2. Используйте категории источника и поиск, отметьте нужные товары. Назначьте категорию магазина отдельно или сразу всем выбранным.
3. Нажмите **Редактировать**: измените название, описание, переводы SR/EN, варианты, SKU, цены в RSD, остатки, фотографии и обложку. Исходные параметры видны во вкладке **Оригинал**.
4. При необходимости пересчитайте цены выбранных вариантов из UAH по своему курсу и наценке. Курс не подставляется автоматически.
5. Проверьте склад, канал продаж, профиль доставки и способ хранения фото. Выбирайте профиль, к которому привязаны нужные способы доставки магазина. Профиль типа `default` или единственный существующий профиль выбирается автоматически; если профилей несколько и `default` нет, выберите нужный вручную. По умолчанию используются ссылки на tamir.ua, новые товары — черновики, остатки — нулевые. Публикация и копирование остатков источника включаются вручную.
6. Нажмите **Проверить и импортировать**, проверьте список и запустите импорт. Страница показывает результат каждого товара и ссылку на карточку.

Правки сохраняются в текущем браузере. Выбор товаров после обновления источника сбрасывается. Если источник или ранее найденный товар изменились, редактор просит сверить данные; принятие текущих данных сохраняет правки, исключает исчезнувшие варианты и добавляет новые без выбора.

Существующий импортированный товар обновляется только с отдельным разрешением в редакторе. Обновление заменяет основные поля, переводы, категорию, профиль доставки, фото, статус, цены и остатки выбранных вариантов на выбранном складе. Невыбранные варианты и другие склады не обнуляются. Переводы сохраняются в стандартном модуле Medusa (`sr-RS`, `en`) и доступны в обычной админке.

При ошибке очередь останавливается. Если создание уже началось, товар остаётся черновиком с указателем на источник. Повтор того же запроса продолжает его обработку; повтор уже завершённого запроса не создаёт дубль. До повтора можно открыть карточку по ссылке и проверить её. Кнопка остановки завершает текущий товар и останавливает следующие.

## Настройка

Дополнительные переменные окружения для обычного импорта не нужны. Используются категории, склады, каналы, профиль доставки и файловый провайдер существующей Medusa. `ROZETKA_STOCK_LOCATION_ID` может задавать предпочитаемый склад; окончательный выбор всегда виден на странице.

Автоперевод необязателен. Для кнопки **Автоперевод SR + EN** нужен серверный `GOOGLE_TRANSLATE_API_KEY` с подключённым Google Translation API. Ключ не отправляется браузеру. Перевод вызывается только нажатием кнопки, отправляет название/описание в Google и оплачивается по тарифу аккаунта. Ручные переводы работают без ключа.

Импорт использует существующие таблицы Medusa; отдельная миграция не нужна. Старый CLI остаётся доступен, но его не следует запускать одновременно с импортом из админки.

## Проверка разработки

В каталоге `backend`:

```sh
node tests/rozetka-admin.test.cjs
npx tsc --noEmit
npx tsc --noEmit -p src/admin/tsconfig.json
npm run build
```

Тест реальных workflow запускается только с отдельной PostgreSQL-базой, имя которой заканчивается на `_import_test`. Он создаёт тестовые категории, склад, канал, товар и переводы; не запускать с рабочей базой:

```sh
# DATABASE_URL должен указывать на отдельную тестовую базу *_import_test.
npx medusa db:migrate
npx medusa exec ./tests/rozetka-native.ts
```

Проверяются предпросмотр категорий, создание только выбранного варианта, RSD-цены, складской остаток, сербский перевод через query.graph, повтор без дубля и обновление цены. Регрессионные тесты дополнительно проверяют ошибки XML/полей, конфликт изменений, снятие блокировки и продолжение после сбоя.

Интерфейс использует семантические цвета Medusa и следует выбранной в админке светлой, тёмной или системной теме, включая редактор, таблицу, поля и сообщения.
