# Импорт Rozetka через админку

Актуально на 11 октября 2026.

Страница: `/app/rozetka`, пункт меню **Импорт Rozetka**. Доступна вошедшим администраторам.

1. Выберите **По ссылке** или **XML-файл**. По умолчанию указан `https://tamir.ua/ua/rozetka/`; адрес можно редактировать (HTTPS на tamir.ua/www.tamir.ua). Кнопка сохранения записывает URL на сервер в `store.metadata.rozetka_source_url`; он доступен после перезагрузки и на другом устройстве. Сохранение адреса само по себе не загружает товары. Файл — XML/YML в UTF-8 до 10 МБ. Нажмите **Загрузить товары**: просмотр не изменяет каталог магазина. Импорт использует именно загруженный источник; изменение поля ссылки без загрузки не переключает каталог. XML-файл не сохраняется в браузерном хранилище: после перезагрузки выберите его снова.
2. Используйте категории источника и поиск, отметьте нужные товары. Назначьте категорию магазина отдельно или сразу всем выбранным.
3. Нажмите **Редактировать**: измените название, описание, переводы SR/EN, варианты, SKU, цены в RSD, остатки, фотографии и обложку. Исходные параметры видны во вкладке **Оригинал**.
4. При необходимости пересчитайте цены выбранных вариантов из UAH по своему курсу и наценке. Курс не подставляется автоматически.
5. Проверьте склад, канал продаж, профиль доставки и способ хранения фото. Выбирайте профиль, к которому привязаны нужные способы доставки магазина. Профиль типа `default` или единственный существующий профиль выбирается автоматически; если профилей несколько и `default` нет, выберите нужный вручную. По умолчанию фото **копируются на сервер** через файловый провайдер Medusa, новые товары — черновики, остатки — нулевые. Внешние ссылки на tamir.ua можно выбрать вручную; тогда доступность фото зависит от источника. Публикация и копирование остатков источника включаются вручную.
6. Нажмите **Проверить и импортировать**, проверьте список и запустите импорт. Страница показывает результат каждого товара и ссылку на карточку.

Черновики редактирования и выбор настроек сохраняются в текущем браузере; это не общий серверный черновик. Только сохранённый URL источника общий для администраторов. Выбор товаров после обновления источника сбрасывается. Если источник или ранее найденный товар изменились, редактор просит сверить данные; принятие текущих данных сохраняет правки, исключает исчезнувшие варианты и добавляет новые без выбора.

Существующий импортированный товар обновляется только с отдельным разрешением в редакторе. Обновление заменяет основные поля, переводы, категорию, профиль доставки, фото, статус, цены и остатки выбранных вариантов на выбранном складе. Невыбранные варианты и другие склады не обнуляются. Переводы сохраняются в стандартном модуле Medusa (`sr-RS`, `en`) и доступны в обычной админке.

При ошибке очередь останавливается. Если создание уже началось, товар остаётся черновиком с указателем на источник. Повтор того же запроса продолжает его обработку; повтор уже завершённого запроса не создаёт дубль. До повтора можно открыть карточку по ссылке и проверить её. Кнопка остановки завершает текущий товар и останавливает следующие.

## Настройка

Дополнительные переменные окружения для обычного импорта не нужны. Используются категории, склады, каналы, профиль доставки и файловый провайдер существующей Medusa. `ROZETKA_STOCK_LOCATION_ID` может задавать предпочитаемый склад; окончательный выбор всегда виден на странице.

Автоперевод необязателен. Для кнопки **Автоперевод SR + EN** нужен серверный `GOOGLE_TRANSLATE_API_KEY` с подключённым Google Translation API. Ключ не отправляется браузеру. Кнопка переводит название/описание; при импорте также автоматически заполняются отсутствующие native-переводы названий опций и их значений. Непустые ручные переводы опций сохраняются. Ошибка автоперевода опций возвращается предупреждением, не маскируется успешным переводом. В админке есть индикатор отсутствующих переводов и отдельная кнопка в виджете опций.

Запросы расходуют квоту Google, включая фоновые операции подготовки EN-контента. Ручные переводы работают без ключа. Проверяйте цвета и термины после перевода; подробности — [LOCALIZATION.md](LOCALIZATION.md).

Основным текстом товара становится подготовленный сербский перевод, если он заполнен; исходный текст сохраняется отдельно. Читаемые адреса SR/EN, aliases старых ссылок и критерий готовности EN описаны в [PRODUCT-SEO.md](PRODUCT-SEO.md). Корзина использует локализованные названия, а исторические заказы не переписываются.

Импорт использует штатные сущности Medusa и служебные таблицы проекта, включая историю адресов `tamir_product_url`. На новом окружении выполните штатные миграции и `setup-reviews.ts` по [DEPLOY.md](../DEPLOY.md). Текущий deploy выполняет setup автоматически. [CLI](IMPORT-MODES.md) остаётся отдельным инструментом; не запускайте его одновременно с импортом из админки.

## Проверка разработки

В каталоге `backend`:

```sh
node tests/rozetka-admin.test.cjs
npx tsc --noEmit
npx tsc --noEmit -p src/admin/tsconfig.json
npm run build
```

Тест реальных workflow запускается только с отдельной PostgreSQL-базой, имя которой заканчивается на `_import_test`. Он создаёт тестовые категории, склад, канал, товар и переводы; не запускать с рабочей базой:

```sh
# DATABASE_URL должен указывать на отдельную тестовую базу *_import_test.
npx medusa db:migrate
npx medusa exec ./tests/rozetka-native.ts
```

Проверяются предпросмотр категорий, создание только выбранного варианта, RSD-цены, складской остаток, сербский перевод через query.graph, повтор без дубля и обновление цены. Регрессионные тесты дополнительно проверяют ошибки XML/полей, конфликт изменений, снятие блокировки и продолжение после сбоя.

Интерфейс использует семантические цвета Medusa и следует выбранной в админке светлой, тёмной или системной теме, включая редактор, таблицу, поля и сообщения.
