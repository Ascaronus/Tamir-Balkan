# Избранное

Макет до реализации: https://www.figma.com/design/2u9V1x7faa2yieZqRP0KaF?node-id=207-3561

Страницы: `/rs/wishlist`, `/en/wishlist`. Они закрыты от индексации; гость видит предложение войти. Кнопка в шапке находится между языком и пользователем и скрыта у гостя. Все сердца используют один `WishlistProvider`, без локального хранилища избранного. Вход из сердца использует существующий `LoginDialog`; после получения профиля и загрузки списка исходный товар добавляется один раз, без перехода.

## Данные и API

`tamir_customer_favorite` хранит только идентификаторы, владельца и дату. Уникальная пара `(customer_id, product_id)` защищает от конкурентных дублей. Внешние ключи удаляют записи при физическом удалении покупателя или товара. Схема добавляется существующим скриптом `setup-reviews.ts` до активации релиза. Миграция аддитивная; откат приложения не требует удаления таблицы.

- `GET /store/wishlist` — идентификаторы текущего покупателя.
- `POST /store/wishlist` с `{ "product_id": "prod_..." }` — идемпотентное сохранение опубликованного товара из канала publishable key. Поля владельца в теле запрещены.
- `DELETE /store/wishlist/:productId` — идемпотентное удаление своей записи, в том числе для недоступного товара.

Владелец берётся из проверенного auth-контекста, дополнительно проверяется существующий аккаунт. Ответы не кэшируются. POST/DELETE подтверждают состояние указанного товара. UI меняет состояние после подтверждения, блокирует повторный клик на время запроса и показывает ошибку при сбое. Повторная загрузка сверяет состояние с сервером; при смене аккаунта состояние создаётся заново. Возвращение фокуса окна обновляет список.

Цены, остатки и тексты загружаются из стандартного Store API партиями по 24 товара с текущим регионом и языком. Снятые с публикации, мягко удалённые, исключённые из канала или не готовые к английской публикации товары показаны без ссылки с кнопкой удаления. Сбой загрузки каталога не выдаётся за недоступность товара.

## Проверки

Изучены PR #35 и `TESTING-RULES.md`. Существующие проверки сохранены. Новые файлы обнаруживаются действующим CI без изменений workflow:

- `frontend/tests/wishlist.test.mjs`: общий store, ошибки, блокировка повторов, устаревшие ответы после выхода, сердца и счётчик SR/EN, вход с однократным продолжением действия, пустой список и недоступный товар.
- `backend/tests/wishlist.test.cjs`: обработчики, авторизация, валидация, канал продаж и изоляция владельца. Medusa/SQL на границе мокируются.
- `backend/tests/wishlist.integration.cjs`: реальный PostgreSQL в изолированной схеме — конкурентная уникальность, удаление, владельцы, внешние ключи. Только `TEST_REVIEWS_DB_URL` с обязательным guard.
- `backend/integration-tests/http/wishlist.spec.ts`: настоящее HTTP, middleware и БД Medusa runner. JWT генерируется только из секрета тестового приложения; реальные аккаунты не используются.
- `verify-localized-routes.mjs`: обе страницы, языки и noindex на собранном Next.

Браузерные E2E не дублируются здесь по правилам репозитория. `Ascaronus/Tamir-QA-Automation` возвращал 404 при подготовке изменения. После предоставления доступа нужны сценарии в этом репозитории: добавление с главной/каталога/товара, гостевой вход и однократное сохранение, отмена входа, удаление, повторный вход/другое устройство, SR/EN, мобильная клавиатура/фокус, отсутствие перехода при клике сердца, регрессия корзины. Эти сценарии пока не реализованы и не считаются пройденными.

## Уточнение оформления 2026-10-30

Сердца экспортированы из Figma без изменения геометрии: узлы `209:3591`
(заливка) и `209:3670` (контур). SVG используются как CSS-маски; активное
сердце и постоянная иконка избранного в шапке окрашиваются существующим

не сжимаются, подпись сохраняет существующие адаптивные правила.

Меню аккаунта сверено с Figma `203:3611`: Manrope Regular 16 px,
межстрочный интервал 22 px, внутренний отступ 20 px, расстояние между
пунктами 12 px. Авторизованный пользователь открывает его наведением мыши
или кнопкой; уход мыши закрывает меню, если клавиатурный фокус не внутри.
Escape, клик снаружи и touch-поведение сохранены. На устройствах без hover
пункты остаются высотой не менее 44 px.
