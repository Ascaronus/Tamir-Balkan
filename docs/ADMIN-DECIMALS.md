# Дробные значения в админке

Размеры и вес товара, его вариантов и складских позиций принимают точку и
запятую: `1,25`, `1.25`, `0,005`. Значение преобразуется в число при сохранении,
а не после каждой клавиши. Пустое необязательное поле очищается; `0` сохраняется.
Отрицательные размеры, бесконечность и неоднозначные значения вроде `1,2,3`
не проходят проверку.

Общий компонент денежных полей принимает оба разделителя для цен товаров,
прайс-листов, доставки, возвратов и денежных бюджетов. Дробная часть ограничена
точностью валюты, которую задаёт форма. Денежный бюджет больше не обрезается
через `parseInt`. Проценты скидок и налоговые ставки также принимают запятую.
Для ввода используются числа без группировки разрядов: `1250,50` или `1250.50`.
Запятая всегда означает дробную часть, поэтому смешанную запись `1,250.50`
нужно заменить на `1250.50`. Числовые значения метаданных поддерживают запятую.

Количество единиц, состав комплектов, лимиты использований и порядковые номера
сохраняют прежние ограничения. Строковые свойства (артикулы, коды, материал)
не меняются. В стандартной Medusa 2.13.1 блок размеров при создании товара
отключён самим Dashboard: размеры товара задаются в его форме Attributes.

## Реализация и обновление

`src/utils/admin-decimal-vite.ts` корректирует конкретные встроенные формы
Dashboard во время сборки и разработки. Зависимости в `node_modules` не
редактируются. Версия Dashboard зафиксирована на 2.13.1. Перед сборкой
проверяются все места замены; несовместимое обновление остановит сборку с
понятной ошибкой, вместо незаметного возвращения ограничения целых чисел.

`src/admin/decimal/currency-input.tsx` сохраняет промежуточный ввод `1,`, даже
если родительская форма хранит числовое значение. В API уходят числа с
обычной десятичной точкой; денежные колонки базы не изменяются.

У `product_variant` и `inventory_item` четыре колонки размеров и веса в Medusa
изначально целочисленные. `setup-decimal-attributes.ts` расширяет их до
PostgreSQL `double precision`, возвращающего JS numbers, внутри транзакции.
Существующие целые значения и NULL сохраняются. Изменение повторяемое; цены
и количество единиц не затрагиваются. Обратное сужение до integer не делается,
поскольку оно потеряло бы дробную часть. После обновления Medusa с миграциями
этот шаг необходимо запускать снова.

`scripts/deploy-vps.sh` выполняет этот шаг автоматически после сборок и проверки
SMTP, до переключения PM2. При блокировке таблиц шаг прервётся через 10 секунд,
старые процессы останутся запущенными. Для отдельного запуска из актуального
каталога backend:

```bash
NODE_ENV=production npx --no-install medusa exec ./src/scripts/setup-decimal-attributes.ts
```

## Проверка

```bash
cd backend
node --test tests/admin-decimals.test.cjs
# Только отдельная тестовая БД, не рабочая DATABASE_URL:
TEST_REVIEWS_DB_URL=postgres://... node --test tests/decimal-attributes.integration.cjs
npm run build
```

CI проверяет преобразование запятой, ноль, пустые/неверные значения,
совместимость исправлений с Dashboard и повторяемость изменения базы с
сохранением дробей. Целочисленные количественные поля проверяются отдельно.
