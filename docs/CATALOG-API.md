# API каталога для нового дизайна

Добавлен `GET /store/catalog/products`. Текущая витрина и стандартный
`GET /store/products` продолжают работать как прежде. Новый интерфейс сможет
подключить этот endpoint без переноса логики фильтрации в браузер.
Изменение не требует миграции базы или новых переменных окружения.

## Заполнение товаров в админке

Размер и цвет задаются **опциями вариантов товара**, например:

- Size / Размер / Розмір / Veličina / Velicina / Величина;
- Color / Colour / Цвет / Колір / Boja / Боја.

Их значения: `M`, `L`, `42,5`, `Crna`, `Bela` и т. п. Используйте одинаковые
названия значений во всём ассортименте. Регистр и пробелы по краям не важны;
перевод синонимов (`Black` → `Crna`) автоматически не выполняется.
Физические ширина/высота/вес не являются одежным размером.
У вариантов должны быть цены в валюте региона. Товар должен быть опубликован
и добавлен в канал продаж ключа витрины.

Товар без опции размера/цвета отображается при отсутствии соответствующего
фильтра. При выборе размера/цвета товары без этой опции не подходят.
Товар без вариантов в новый каталог не включается.

## Запрос

Нужен обычный заголовок `x-publishable-api-key` витрины. Для персональных цен
передавайте Bearer JWT покупателя или его сессию: используются штатные группы
покупателей Medusa. Для расчёта остатков ключ должен иметь один канал продаж,
как у текущей витрины. Ключи администратора в браузер не передаются.

```bash
curl -G 'https://BACKEND_HOST/store/catalog/products' \
  -H 'x-publishable-api-key: PUBLISHABLE_KEY' \
  --data-urlencode 'region_id=reg_REPLACE_ME' \
  --data-urlencode 'country_code=rs' \
  --data-urlencode 'size=M' \
  --data-urlencode 'size=L' \
  --data-urlencode 'color=Crna' \
  --data-urlencode 'min_price=1500,50' \
  --data-urlencode 'max_price=5000' \
  --data-urlencode 'sort=price_asc' \
  --data-urlencode 'limit=24' \
  --data-urlencode 'offset=0'
```

| Параметр | Правило |
| --- | --- |
| `region_id` | Обязателен; задаёт регион и валюту цены |
| `country_code`, `province` | Страна и необязательная область для налогов; область требует страну |
| `category_id` | Необязательная активная публичная категория |
| `q` | Штатный текстовый поиск Medusa, до 200 символов |
| `size`, `color` | Один или несколько повторяющихся параметров, максимум 20 значений по 80 символов |
| `min_price`, `max_price` | Включительные границы, неотрицательные суммы, точка или запятая, до 4 дробных знаков |
| `sort` | `newest` (по умолчанию), `price_asc`, `price_desc`, `popularity` |
| `limit` | От 1 до 100, по умолчанию 24 |
| `offset` | От 0 до 10000, по умолчанию 0 |

Повторяйте параметры: `size=M&size=L`. **Не соединяйте значения запятой**:
`size=42,5` означает один дробный размер. Размер, цвет и цена объединяются
через И и должны совпасть у **одного варианта**. Внутри списка размеров или
цветов применяется ИЛИ. Один товар в выдаче всегда появляется один раз.

Цена передаётся в основных единицах валюты Medusa 2: `1500.50` означает
1500,50 RSD, а не 15,005 RSD. Используется рассчитанная цена варианта для
региона и группы покупателя, включая действующий прайс-лист. Если передана
страна и в регионе включены автоматические налоги — берётся цена с налогом;
иначе используется `calculated_amount`, как в штатном Store API.
Для согласованного отображения передавайте одинаковый регион/страну в каталоге,
карточке товара и корзине. Купонные скидки корзины и доставка сюда не входят.

## Ответ

Структура страницы: `products`, точный `count`, `offset`, `limit`, `sort`,
`currency_code`, `sort_options`, `filters`, `applied_filters`.
`products` содержит обычные публичные поля Store Product с рассчитанными
ценами вариантов и остатками. Каждый товар дополнен объектом:

```json
{
  "catalog": {
    "price": 1990.5,
    "currency_code": "rsd",
    "matching_variant_ids": ["variant_EXAMPLE"],
    "preferred_variant_id": "variant_EXAMPLE"
  }
}
```

`catalog.price` — минимальная цена **подходящих** вариантов. Показывайте её
на карточке каталога; для выбора размера/цвета при переходе используйте
`preferred_variant_id`. Все варианты сохранены в стандартном поле `variants`.
Обе сортировки по цене используют эту минимальную цену; `price_desc` меняет
направление. Варианты без цены не подходят под ценовой фильтр. Без фильтра
товары без цены остаются и идут в конце обеих ценовых сортировок с `price: null`.
Бесплатная цена `0` считается настоящей ценой.

Пример `filters`:

```json
{
  "sizes": [{ "value": "l", "label": "L", "count": 12 }],
  "colors": [{ "value": "crna", "label": "Crna", "count": 8 }],
  "price": { "min": 1500.5, "max": 6900, "currency_code": "rsd" }
}
```

Для подписи показывайте `label`, в запрос отправляйте `value`. Количество —
число товаров, а не вариантов. Список размеров учитывает цвет и цену, но
игнорирует выбранный размер; список цветов учитывает размер и цену, но
игнорирует выбранный цвет. Границы цены учитывают размер и цвет, игнорируя
выбранные границы. Категория, поиск и доступность канала действуют всегда.
При отсутствии цен границы равны `null`, а не нулю. Если выбранное значение
исчезло из доступных вариантов, сохраняйте его в UI по `applied_filters`, чтобы
покупатель мог снять фильтр. При изменении фильтров/сортировки сбрасывайте
`offset` в 0. При быстрой смене фильтров отменяйте устаревшие запросы.

## Сортировка и популярность

- `newest`: по дате создания товара, новые первыми.
- `price_asc` / `price_desc`: от дешёвых / от дорогих.
- `popularity`: количество единиц в **завершённых** заказах за всё время
  в текущем регионе и канале витрины, за вычетом принятых возвратов и списаний.

Заказы в статусе `pending`, черновики, отменённые и удалённые заказы не
участвуют. Одна оплата сама по себе не делает заказ `completed`: если магазин
не завершает заказы в Medusa, популярность будет равной нулю. Старые версии
позиций заказа не суммируются повторно. Нет продаж — выше новые товары.
При равных ценах/популярности сначала новые, затем стабильная сортировка по ID.
Личные данные покупателей и содержимое заказов API каталога не возвращает.

## Ограничения и проверка

Неизвестные параметры, неверные числа и `min_price > max_price` дают HTTP 400.
Пользователь не может передать собственный статус публикации, произвольные
поля, ID покупателя, чужой канал или `with_deleted`.
Новый endpoint защищён штатной проверкой publishable key. Ограничение по
связи товара с каналом применяется даже при единственном канале.

Расчёт выполняется до пагинации по всему подходящему ассортименту, порциями
по 200 товаров. Описания, изображения и остатки загружаются только для страницы.
Персональная выдача не кешируется: `Cache-Control: private, no-store`.
Это точный расчёт с ценовым движком Medusa, а не отдельный поисковый индекс.
При более чем 10000 кандидатах ответ HTTP 503 с `CATALOG_SCOPE_TOO_LARGE`
предлагает сузить поиск/категорию. Частичная выдача не выдаётся за полный каталог.
Перед расширением ассортимента/нагрузки нужен нагрузочный тест и, при
необходимости, отдельный индекс. Фильтры размера/цены сами по себе этот лимит
не уменьшают — они применяются после загрузки кандидатов.

Код использует экспортируемые Store helpers Medusa 2.13.1. При обновлении
Medusa обязательно запускать тесты middleware и сборку.

```bash
cd backend
node --test tests/catalog.test.cjs tests/catalog-http.test.cjs
# Только отдельная тестовая база:
TEST_REVIEWS_DB_URL=postgres://... node --test tests/catalog-popularity.integration.cjs
npm run build
```

Тесты проверяют сочетания вариантов, дроби и ноль, скидки/налоги, группы
покупателей, границы, счётчики фильтров, сортировку до пагинации, ограничения
каналов и SQL подсчёта популярности на PostgreSQL. Они включены в GitHub CI.
Для локального SQL-теста без сервера PostgreSQL допустима внешняя установка
PGlite с указанием пути через `CATALOG_TEST_PGLITE_PATH`.
