# CLI-импорт XML и режимы синхронизации

Актуально на 11 октября 2026. Для выбора товаров и ручной подготовки используйте [импорт в админке](ROZETKA-ADMIN-IMPORT.md). Скрипт `backend/src/scripts/import-rozetka-xml.ts` — отдельный пакетный инструмент, без экрана выбора и сохранённых браузерных черновиков. Не запускайте эти два механизма одновременно.

## Запуск

Из каталога backend нужного релиза, с его окружением и резервной копией базы:

```bash
export ROZETKA_XML_URL='https://tamir.ua/ua/rozetka/'
export ROZETKA_STOCK_LOCATION_ID='sloc_REPLACE_ME'
export ROZETKA_IMPORT_MODE=incremental
export ROZETKA_UPDATE_EXISTING=true
export ROZETKA_UPLOAD_IMAGES=true
npx medusa exec ./src/scripts/import-rozetka-xml.ts
```

Замените `sloc_REPLACE_ME` на реальный склад. Команда изменяет каталог и остатки; это не предпросмотр. В CLI старый fallback URL всё ещё `https://tamir.ua/rozetka/`, поэтому задавайте правильный украинский источник явно. Сохранённый в админке адрес не заменяет эту переменную.

- `ROZETKA_DRY_RUN=true` — проверить фид, обязательные настройки и варианты без записи. По умолчанию выключен; для первой проверки добавьте эту переменную перед запуском. Проверка может обращаться к источнику и сервису курса.
- `ROZETKA_SALES_CHANNEL_ID` — канал продаж; если не задан, используется default sales channel магазина. Требуется профиль доставки типа `default`.
- `ROZETKA_UPDATE_EXISTING=true` — значение по умолчанию: обновлять найденные товары. `false` исключает их обновление и несовместимо с полным режимом.
- `ROZETKA_UPLOAD_IMAGES=true` — по умолчанию копировать изображения в файловый провайдер Medusa; `false` оставляет внешние ссылки.
- `ROZETKA_STOCK_LOCATION_ID` — склад; резервная переменная — `STOCK_LOCATION_ID`.
- `ROZETKA_UAH_TO_RSD` — положительный курс для пересчёта UAH → RSD. Если не задан, CLI запрашивает курс у `fxapi.app`; отсутствие корректного курса останавливает импорт до записи товаров. В админском редакторе курс вводится отдельно вручную.
- `GOOGLE_TRANSLATE_API_KEY` — необязательный серверный ключ перевода; [настройка и ограничения](LOCALIZATION.md).

Остальные параметры и точная логика сопоставления CLI находятся в [скрипте](../backend/src/scripts/import-rozetka-xml.ts). Не считайте CLI и админский импорт взаимозаменяемыми по всем полям.

## Incremental и full

По умолчанию `ROZETKA_IMPORT_MODE=incremental`: обновляются предложения текущего файла; отсутствие предложения не означает обнуление.

`ROZETKA_IMPORT_MODE=full` требует `ROZETKA_UPDATE_EXISTING=true`. После успешного обновления товаров и остатков отсутствующие в полном файле варианты этого источника получают нулевой остаток только на выбранном складе. Пустой фид отклоняется. При ошибке предыдущих этапов сверка отсутствующих предложений не запускается.

Источник записывается в `metadata.rozetka_feed_source` варианта как хеш полного URL фида. Не меняйте URL без проверки связи с прежним источником. Товары других источников и немаркированные старые товары не обнуляются. Первый импорт маркирует присутствующие предложения; старые предложения, отсутствующие уже в первом файле, требуют ручной проверки принадлежности источнику.

Полный импорт не является одной транзакцией. После сбоя исправьте причину и повторите импорт; сверка отсутствующих предложений выполняется последней. Запускайте один импорт за раз. Удаление товара из файла не удаляет сам товар магазина.
