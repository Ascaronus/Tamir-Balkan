# CLI XML Import and Sync Modes

Актуально на 18 ноября 2026. Для выбора товаров и ручной подготовки используйте [импорт в админке](ROZETKA-ADMIN-IMPORT.md). Скрипт `backend/src/scripts/import-rozetka-xml.ts` — отдельный пакетный инструмент, без экрана выбора и сохранённых браузерных черновиков. Не запускайте эти два механизма одновременно.

## Running

Из каталога backend нужного релиза, с его окружением и резервной копией базы:

```bash
export ROZETKA_XML_URL='https://tamir.ua/ua/rozetka/'
export ROZETKA_STOCK_LOCATION_ID='sloc_REPLACE_ME'
export ROZETKA_IMPORT_MODE=incremental
export ROZETKA_UPDATE_EXISTING=true
export ROZETKA_UPLOAD_IMAGES=true
npx medusa exec ./src/scripts/import-rozetka-xml.ts
```

Замените `sloc_REPLACE_ME` на реальный склад. Команда изменяет каталог и остатки; это не предпросмотр. В CLI старый fallback URL всё ещё `https://tamir.ua/rozetka/`, поэтому задавайте правильный украинский источник явно. Сохранённый в админке адрес не заменяет эту переменную.

- `ROZETKA_DRY_RUN=true` — проверить фид, обязательные настройки и варианты без записи. По умолчанию выключен; для первой проверки добавьте эту переменную перед запуском. Проверка может обращаться к источнику и сервису курса.
- `ROZETKA_SALES_CHANNEL_ID` — канал продаж; если не задан, используется default sales channel магазина. Требуется профиль доставки типа `default`.
- `ROZETKA_UPDATE_EXISTING=true` — значение по умолчанию: обновлять найденные товары. `false` исключает их обновление и несовместимо с полным режимом.
- `ROZETKA_UPLOAD_IMAGES=true` — по умолчанию копировать изображения в файловый провайдер Medusa; `false` оставляет внешние ссылки.
- `ROZETKA_STOCK_LOCATION_ID` — склад; резервная переменная — `STOCK_LOCATION_ID`.
- `ROZETKA_UAH_TO_RSD` — положительный курс для пересчёта UAH → RSD. Если не задан, CLI запрашивает курс у `fxapi.app`; отсутствие корректного курса останавливает импорт до записи товаров. В админском редакторе курс вводится отдельно вручную.
- `GOOGLE_TRANSLATE_API_KEY` — необязательный серверный ключ перевода; [настройка и ограничения](LOCALIZATION.md).

Остальные параметры и точная логика сопоставления CLI находятся в [скрипте](../backend/src/scripts/import-rozetka-xml.ts). Не считайте CLI и админский импорт взаимозаменяемыми по всем полям.

## SKU по артикулу из фида

SKU варианта строится из артикула: последнего сегмента адреса `<url>` без `.html` в верхнем регистре, к которому через дефис добавляется значение параметра `Размер`. `.../baf-tmr-1black.html` с `Размер=One Size` даёт `BAF-TMR-1BLACK`, а `.../shtani-tmr-2211m43021-siri.html` с `Размер=48` — `SHTANI-TMR-2211M43021-SIRI-48`. Товары без параметра `Размер` и с `Размер=One Size` остаются на одном артикуле; если в адресе нет читаемой латиницы, используется прежний SKU из `id`. Формула общая для CLI и админского импорта: технический `id` предложения в SKU больше не попадает, а `metadata.rozetka_offer_id`, `rozetka_url`, `rozetka_article` и `rozetka_legacy_sku` — служебные поля для трассировки и ретро-скрипта.

Товар ищется по `metadata.rozetka_product_key`, и этим ключом в обоих механизмах служит адрес товара из фида. CLI берёт `<url>` предложения без query, hash и хвостового слэша (`productKeyFromOffer`) и по нему же группирует офферы одного товара в карточку. Админка пишет в `rozetka_product_key` адрес товара источника и дополнительно `rozetka_admin_key` — дайджест источника импорта, по которому товар тоже находится. Следствие: один и тот же товар, полученный из `https://tamir.ua/ua/rozetka/` и из `https://tamir.ua/rozetka/`, даёт разные ключи, и импорт из «чужого» адреса создаёт вторую карточку вместо обновления существующей — адреса в этих фидах различаются префиксом `/ua/`. Вариант ищется по SKU, и только если совпадения нет — по значению опции `Size`; ни `rozetka_offer_id`, ни `rozetka_url` для сопоставления вариантов в CLI не участвуют.

При повторных импортах важно, что оба механизма видят только живые строки: Medusa исключает `deleted_at is not null` из всех запросов, а уникальные индексы `product.handle` и `product_variant.sku` частичные (`where deleted_at is null`). Карточка, удалённая в админке, для импорта не существует, и импорт пишет новую живую карточку с тем же адресом и теми же SKU, а удалённая строка остаётся в базе. Ретро-скрипт `fix-rozetka-sku.ts` работает так же только с живыми вариантами и считает SKU удалённого варианта свободным — конфликтуют между собой только живые SKU.

Дефект старых сборок был не в дублях карточек: фид-парсер группирует предложения одного товара в одну карточку, и CLI находит её по `rozetka_product_key`. Прежний SKU собирался из технического `id` предложения и не совпадал с артикулом в Розетке, из-за чего карта остатков `skuToStock` и сверка остатков полного импорта `missingSourceInventory` не совпадали с предложениями фида, а товар нельзя было узнать по артикулу. Карточки, импортированные старыми сборками, правит отдельный скрипт:

```bash
export ROZETKA_XML_URL='https://tamir.ua/ua/rozetka/'
npx medusa exec ./src/scripts/fix-rozetka-sku.ts                             # только предпросмотр
ROZETKA_SKU_FIX_APPLY=true npx medusa exec ./src/scripts/fix-rozetka-sku.ts  # запись
```

Из каталога `backend` тот же прогон доступен как `npm run fix:rozetka:sku`. По умолчанию скрипт ничего не пишет; запись включает `ROZETKA_SKU_FIX_APPLY=true`. `ROZETKA_SKU_FIX_BATCH` задаёт размер пачки вариантов в одном вызове workflow (по умолчанию 25). Источник берётся из первого аргумента, затем из `ROZETKA_XML_URL`, иначе используется `https://tamir.ua/ua/rozetka/` — у этого скрипта адрес по умолчанию уже корректный, в отличие от CLI-импорта.

Скрипт меняет `sku` только у вариантов импорта Розетки и синхронизирует `sku` их инвентарных элементов, поэтому уровни остатков сохраняются; цены, названия, опции и товары других источников не затрагиваются. Артикул и прежний SKU сохраняются в `metadata.rozetka_article` и `metadata.rozetka_legacy_sku`. Предложения, исчезнувшие из фида, остаются со старым SKU и только выводятся в отчёт. Повторный запуск безопасен: уже исправленные варианты попадают в счётчик «уже корректно», конфликтующие SKU не применяются и выводятся в отчёт.

**Порядок действий обязателен: сначала `fix-rozetka-sku.ts` (предпросмотр, затем запись с `ROZETKA_SKU_FIX_APPLY=true`), и только потом импорт.** Полный режим обнуляет остатки вариантов этого источника, которых нет в снимке фида: `missingSourceInventory` ([import-scope.ts](../backend/src/utils/import-scope.ts)) вызывает сверку в конце импорта, и сопоставление идёт по SKU. Пока в базе прежние id-SKU, они не совпадут с артикульными SKU из фида, и `ROZETKA_IMPORT_MODE=full` обнулит остатки исправляемых карточек. В инкрементальном режиме обнуления нет, но вариант может найтись по значению `Size` и получить новый SKU, а часть строк останется несопоставленной. Ретро-скрипт и импорт из админки используют один и тот же блокировочный advisory-lock, поэтому одновременно они не выполняются; CLI-импорт тоже запускайте отдельно.

## Incremental and Full

По умолчанию `ROZETKA_IMPORT_MODE=incremental`: обновляются предложения текущего файла; отсутствие предложения не означает обнуление.

`ROZETKA_IMPORT_MODE=full` требует `ROZETKA_UPDATE_EXISTING=true`. После успешного обновления товаров и остатков отсутствующие в полном файле варианты этого источника получают нулевой остаток только на выбранном складе. Пустой фид отклоняется. При ошибке предыдущих этапов сверка отсутствующих предложений не запускается. Перед первым полным импортом после перехода на артикульные SKU обязательно выполните ретро-фиксацию SKU из раздела выше, иначе обнулятся остатки карточек со старыми SKU.

Источник записывается в `metadata.rozetka_feed_source` варианта как хеш полного URL фида. Не меняйте URL без проверки связи с прежним источником. Товары других источников и немаркированные старые товары не обнуляются. Первый импорт маркирует присутствующие предложения; старые предложения, отсутствующие уже в первом файле, требуют ручной проверки принадлежности источнику.

Полный импорт не является одной транзакцией. После сбоя исправьте причину и повторите импорт; сверка отсутствующих предложений выполняется последней. Запускайте один импорт за раз. Удаление товара из файла не удаляет сам товар магазина.
