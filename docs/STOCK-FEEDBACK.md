# Остатки в карточке и корзине

Карточка показывает только локализованный статус «В наличии» / «Нет в наличии» / предзаказ.
Количество, уже выбранное самим покупателем в корзине, остаётся видимым. Поле количества
не ограничивается устаревшим остатком из карточки и не раскрывает его через HTML max.

Добавление и изменение количества по-прежнему выполняются стандартными мутациями Medusa.
При отказе `Some variant does not have the required inventory` клиент один раз запрашивает
`/store/products` с фильтром `variants.id`, каналом продаж корзины и полем
`variants.inventory_quantity` (`cache: no-store`). Эта величина в установленной Medusa
рассчитывается через `getVariantAvailability` по доступным складам канала и required_quantity
компонентов варианта; available_quantity склада — stocked_quantity минус reserved_quantity.
Повторно вычитать резерв на клиенте нельзя.

После отказа показывается доступное общее количество варианта, а при добавлении также
количество этого варианта, уже находящееся в корзине. Для добавления проверяется существующее
количество плюс добавляемое, для изменения — новое количество вместо старого количества строки.
Это пояснение серверного отказа, а не клиентский механизм резервирования. Наличие товара
в незавершённой корзине само по себе не создаёт новый резерв.

Успешные мутации не делают дополнительного запроса остатков. Ошибки сети и неизвестные
ошибки остаются общими. Если уточнение не удалось, ответ не содержит количества, либо
свежая доступность уже покрывает запрос, число не выдумывается. Повторной автоматической
попытки добавления из-за ошибки остатков нет. Между отказом и уточнением остаток может
измениться; окончательное решение всегда остаётся за Medusa.

Изменений БД, серверных маршрутов и логики резервирования нет. Покрыты SR/EN, скрытый
остаток до действия, превышение остатка, позиции уже в корзине, замена количества строки,
нулевая доступность, сбой уточнения и сохранение поведения успешных мутаций.
