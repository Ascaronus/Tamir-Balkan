# Sitemap, robots и Google Search Console

Актуально на 12 октября 2026. Публичные файлы: [robots.txt](https://tamir.rs/robots.txt) и [sitemap.xml](https://tamir.rs/sitemap.xml). Источники реализации — `frontend/src/app/robots.ts`, `sitemap.ts` и общий SEO-код витрины.

## Что включено в sitemap

- Обе главные: `/rs` и `/en`, без перенаправления в каталог.
- Локализованные страницы terms/privacy/cookies.
- Все доступные витрине SR-товары, а EN-товары — только с готовыми английскими названием/описанием и адресом.
- Непустые публичные категории с локализованными адресами и индексируемые страницы пагинации каталога/категорий.

Загрузка товаров проходит все страницы Store API, а не ограничивается первой сотней. Учитываются публикация, канал продаж и доступность записи витрине. Черновики не обязаны совпадать по количеству с sitemap. Новые доступные товары появляются без деплоя. `lastmod` товара берётся из корректного `updated_at`.

Первая страница общего `/rs/catalog` канонизирована на `/rs`, `/en/catalog` — на `/en`. Фильтры и сортировки не создают отдельные записи sitemap. Пары SR/EN связаны hreflang; для неготового EN-товара не публикуется ложная готовая альтернатива. [Критерии EN](LOCALIZATION.md).

## Индексация и ожидаемые исключения

| Ситуация в Search Console | Поведение проекта |
| --- | --- |
| Страница с переадресацией | Прежние категории/служебные URL ведут на текущий адрес. Старые товарные URL возвращают 404 без перенаправления |
| Вариант с canonical | `?v_id=...`, сортировка и фильтры указывают на основную страницу. Вариант товара при этом остаётся выбранным в интерфейсе |
| `noindex` | Кабинет, корзина, checkout, заказ, внутренний поиск, пустые категории и неготовые EN-карточки исключены намеренно; 404 также может содержать noindex |
| Google выбрал другой canonical | Проверьте конечный ответ, canonical/hreflang, внутренние ссылки и sitemap одного и того же URL; не отменяйте полезные redirects ради исчезновения строки отчёта |

`robots.txt` блокирует `/api/`. Приватные страницы доступны роботу для чтения `noindex, nofollow`, но это не заменяет авторизацию. Публичные главные, заполненные категории/товары и legal-страницы не имеют общего запрета индексации. `.woff2`, robots.txt и sitemap.xml — технические ресурсы, не товарные страницы для sitemap.

## Проверка и отправка

Один существующий ресурс Search Console для `tamir.rs`, охватывающий оба пути, обслуживает SR и EN; отдельный домен/ресурс только ради EN не нужен. Отправьте `https://tamir.rs/sitemap.xml` в разделе «Файлы Sitemap». Robots отдельно отправлять не требуется.

```bash
curl -fsS https://tamir.rs/robots.txt
curl -fsS https://tamir.rs/sitemap.xml
curl -I https://tamir.rs/rs
curl -I https://tamir.rs/en
```

Для проблемного товара проверяйте **точный URL**, конечный HTTP-статус, HTML canonical/hreflang/robots, HTTP `X-Robots-Tag` и дату последнего обхода. Используйте проверку опубликованной страницы в Search Console. Старый отчёт не обновляется в момент деплоя; отправка не гарантирует индексацию.

Если sitemap недоступен или неполон, проверьте `/health` backend, публикацию, связь с каналом publishable key, переводы и логи frontend. Не подменяйте ошибку API пустым успешным sitemap. Общий `X-Robots-Tag: noindex` в nginx/CDN не задаётся приложением — проверяйте внешнюю конфигурацию отдельно.

Обновление сервера: [DEPLOY.md](../DEPLOY.md). Структурированные данные и подтверждённые ограничения контента: [PRODUCT-SEO.md](PRODUCT-SEO.md).

## Обновление внутренних ссылок — 12 октября 2026

Меню «Все товары», футер, ссылки возврата и сброса ведут на `/rs` / `/en`, совпадая с canonical первой страницы. Генератор пагинации возвращает на эту же главную при выборе первой страницы без фильтров и сортировки. Последующие страницы сохраняют `/catalog?page=N`, категории — собственные адреса. Старый `/catalog` остаётся доступным с canonical главной. Страница пагинации за пределами текущего числа товаров возвращает 404, а не пустой индексируемый 200; сбой backend не считается доказательством удаления страницы.

Обычная карточка ведёт на чистый адрес товара, если выбран его стандартный вариант. Явный выбор цвета или вариант, подходящий фильтру, сохраняет `v_id`, когда без него открылась бы другая вариация. В JSON-LD товара с единственным вариантом Offer URL совпадает с чистым адресом; у нескольких вариантов остаются конкретные selectable URL. Canonical всех вариантов по-прежнему указывает на товар. Цель — согласованные ссылки, а не принудительная индексация каждого параметра.

## Что делать при замене товара

| Ситуация | Действие |
| --- | --- |
| Тот же товар: меняются фото, цена, описание или перевод | Редактируйте существующую карточку, сохраняйте ID и URL |
| Товар временно закончился | Оставьте полезную опубликованную карточку с честным нулевым остатком; не удаляйте URL только из-за отсутствия на складе |
| Та же карточка получает новый адрес | По политике владельца старый товарный URL возвращает 404. EN-виджет сохраняет историю резерва адресов, но resolver её не обслуживает |
| Старый товар удалён, затем импортирован снова | Это новая карточка. Старые отличающиеся адреса возвращают 404, даже при совпадении модели поставщика |
| Товар удалён окончательно, подходящей замены нет | Корректный 404/410 допустим; уберите старую карточку из внутренних ссылок/sitemap, не перенаправляйте все ошибки на главную |

Не превращайте старую карточку шарфа в несвязанную карточку другого товара ради сохранения индексации: это также смешивает отзывы и товарную историю. Редактирование перевода, импорт и изменение URL — разные операции. Товарные перенаправления отключены по решению владельца. Не редактируйте служебные URL-таблицы произвольным SQL.

### Повторный импорт после удаления

Повторно импортированный товар считается новой карточкой. Resolver не ищет замену в soft-deleted товарах, не читает `rozetka_legacy_handle` и не обслуживает строки `tamir_product_url` с `is_current=false`. Он нужен только для текущего английского адреса опубликованного неудалённого товара; доступность каналу затем проверяет Store API.

Витрина принимает только текущий handle выбранного языка. Старые/чужие языковые адреса дают 404 с noindex, в том числе с `v_id`; перенаправления на другой товар или главную нет. Сбой API не маскируется под удаление. Переключатель языка использует актуальные SR/EN-ссылки.

Sitemap и внутренние ссылки строятся из текущих доступных товаров, без исторических URL. После удаления и импорта вручную редактировать sitemap не нужно. Если нынешний товар использует точно тот же URL, что прежний, этот действующий URL остаётся 200: один адрес нельзя одновременно обслуживать и считать удалённым. Текущие адреса специально не переименовываются.

Удаление старых публичных адресов не требует физического удаления истории заказов, отзывов или soft-deleted строк. Старые адреса постепенно исключаются из поиска после повторного обхода; записи 404 могут оставаться в Search Console и не означают поломку текущих карточек.

Строки «Страница с переадресацией» и «Вариант страницы с тегом canonical» для ожидаемых старых/параметрических адресов не требуют удаления защиты от дублей. Проверка исправления может не пройти, пока URL намеренно остаётся redirect/alternate; контролируйте индексацию конечной основной страницы. Robots, sitemap, favicon и шрифты не обязаны появляться в поисковой выдаче как страницы магазина. Отправка sitemap и запрос индексирования не дают гарантированного срока или включения в индекс.

Официальные пояснения Google: [отчёт об индексировании](https://support.google.com/webmasters/answer/7440203), [адреса интернет-магазина](https://developers.google.com/search/docs/specialty/ecommerce/designing-a-url-structure-for-ecommerce-sites), [удалённые и перемещённые страницы](https://developers.google.com/search/docs/crawling-indexing/troubleshoot-crawling-errors).
